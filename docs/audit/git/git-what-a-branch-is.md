# What a branch really is (`content/git/02-branches/01-git-what-a-branch-is/`)

- **Track / Part:** Git - Part 2 Branches
- **Engine / format:** viz (MemoryViz with `repo` scene, narrated)
- **Difficulty pill:** Gentle  **XP cards (data-total):** 1
- **Runnable:** no (theory - watch only)  **Theme:** animals (cat.txt, dog.txt, bird.txt)

## Concept(s) taught
A branch is not a copy of the project - it is a name pointing at a commit. `HEAD` is the marker for which branch you are on, and it decides which name moves when you commit.

## Card-by-card
| # | Step | Concept | What the learner sees |
|---|---|---|---|
| 1-6 | What a branch really is | Branch, HEAD | Watch `git branch feature` add a name, `git switch` move `HEAD`, and a commit move only the name `HEAD` points at. 6 narrated steps. |

## Prerequisites
Lessons 1-3 (commits, history, `git log`). The learner has seen a single-branch graph (`main`) and knows commits chain. This lesson introduces the second name and the marker that chooses between them.

## Complexity rung
A conceptual jump: from one line of work to two. The key teaching is negative - "**nothing was copied**" (step 2) - because the wrong mental model (branch = duplicate folder) is the specific obstacle this lesson removes.

## Covered well
- **The lesson argues against the wrong picture.** Step 2's narration explicitly says "nothing was copied" and "There is no second set of commits." This is the right pedagogy: name the misconception, show the truth.
- **The visual makes the argument.** Every step shows the SAME commits with only labels moving - the learner sees directly that nothing duplicates.
- The sequence (make a name, move `HEAD`, commit, watch which name moves) previews exactly what lesson 5 will ask the learner to type.

## Gaps / issues

**Theory mirrors practice, per the owner's complaint.** Let me check what lesson 5 (`git-make-a-branch`) shows on the practical board. Lesson 5's cards:
- Card 1: `git branch feature` (make a name, do not move).
- Card 2: `git switch -c feature`, `git add dog.txt`, `git commit` (make, move, commit on the new line).

This theory lesson shows: make a name (step 2), move `HEAD` (step 4), commit on the new line (step 5). That is the SAME sequence the practical board will display when the learner types those commands in lesson 5. The only difference is narration text vs typing commands - the visual is identical.

**What this lesson DOES add over lesson 5:**
- It shows the sequence BEFORE the learner types it, so they know the expected outcome.
- The narration names the teaching point: "A branch is a name that moves forward as you commit" (step 6).
- It explicitly kills the "branch = copy" misconception (step 2).

**But:** lesson 5's `intro` and card `context` prose could state the same points in text, making this visual redundant. The ratified decision in `git-track-depth.md` says theory should explain the MODEL (internal structure), not re-display the tool's output.

**What is missing (per the new theory bar):** This lesson shows labels moving but never shows WHAT A BRANCH HOLDS. If branches carried file contents, step 5 could show: "`feature` now points at a commit holding `cat.txt`, `dog.txt`, `bird.txt`, while `main` still points at a commit with only `cat.txt` and `dog.txt` - same files up to the split, then diverging." That would be MODEL explanation; the current lesson is tool observation.

**Actionable fixes (per `git-track-depth.md` phase 2 "surfaces: file-text panel for theory"):**
1. **Add a file-list panel showing what each branch's tip commit holds.** Step 1: `main` at commit 2 holds `[cat.txt, dog.txt]`. Step 5: `feature` at commit 3 holds `[cat.txt, dog.txt, bird.txt]`; `main` still at commit 2 holds `[cat.txt, dog.txt]`. This makes "the name points at a commit, and the commit holds files" concrete instead of abstract.
2. **Show `HEAD` as the decisive pointer.** Add a third panel: "Your working tree currently shows the files from the commit `HEAD` points at. When `HEAD` moves (step 4), the files in your folder ALSO change to match the new commit." This explains WHY `HEAD` matters (it controls what you see), not just that it exists.
