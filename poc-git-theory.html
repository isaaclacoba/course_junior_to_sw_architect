C. The playground - the one thing the learner touches

Reused across lessons. No commands, no grading - type content, watch it get a name.

hello world
blob 12\0hello world\n
→
SHA-1
3b18e512dba79e4c8300dd08aeb37f8e728b8dad stored at .git/objects/3b/18e512dba79e4c8300dd08aeb37f8e728b8dad

Type it on your own machine: echo "hello world" | git hash-object --stdin - same forty characters.

Change one letter and every character of the name changes. Change it back and the old name returns.

D. One scene, three lenses - not three widgets

Same stored state below, rendered three ways. A step declares lens: "folder" | "chain" | "both".

LensWhat it answersThe lesson that needs it
folder (B1)Where does this live, and what is literally in it? Anything that introduces a NEW KIND OF FILE in .git: blob, tree, commit, refs/heads/main, HEAD, the index, a packfile, refs/remotes/
chain (B2)Who names whom? Anything about a RELATIONSHIP: tree to blob, commit to tree, commit to parent, ref to commit, "unreachable" = nobody points at it, rebase making copies
both (B3)Are these two pictures the same thing? The first complete save, end to end - and the closing recap of each part

One scene, one data shape, one place to fix a bug. The lens is chosen per STEP, so a lesson can open on the folder and close on both.
